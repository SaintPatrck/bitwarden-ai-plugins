# Bitwarden Initiative Tools

Bitwarden's Software Initiative Funnel — the phase-by-phase mechanics of moving an initiative through the funnel, and the playbook for handing ownership between teams.

## Overview

This plugin holds the agent-neutral funnel, strategy-idea, and work-transition skills that any role can compose while participating in an initiative.

## Skills

| Skill                                      | Triggers                                                                     | Purpose                                                                                                              |
| ------------------------------------------ | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `navigating-the-initiative-funnel`         | "initiative funnel", "scoping & commitment", "shepherd"                      | Phase-by-phase participation across Bitwarden's Software Initiative Funnel.                                          |
| `running-work-transitions`                 | "work transition", "handoff", "transition playbook"                          | Both-sides playbook for receiving or originating ownership transitions (initiatives, frameworks, runbooks).          |
| `championing-a-strategy-idea`              | "I'm Primary Owner on ARCH-…", "Adoption Retrospective"                      | Primary-Owner playbook for shepherding a Technical Strategy Idea through pre-funnel evaluation into the funnel.      |
| `curating-the-strategy-ideas-backlog`      | "I'm peer reviewer on ARCH-…", "quarterly RICE scoring"                      | Peer-Reviewer and portfolio-curator side of the TSI Shepherding Model — backlog stewardship and prioritization.      |
| `shepherding-an-initiative`                | "ARCH-X just got approved", "I'm assigned shepherd"                          | Five-phase umbrella playbook for an initiative shepherd; dispatches to the phase deep-dives below.                   |
| `running-an-architectural-assessment`      | "starting Research phase", "drafting the Architectural Assessment"           | Phase 2 (Research) deep-dive — drafts the Architectural Assessment.                                                  |
| `running-a-proof-of-concept`               | "PoC time", "building the PoC", "drafting the ADR"                           | Phase 3 (Proof of Concept) deep-dive — validates the Research recommendation in real code and drafts the ADR.        |
| `scoping-and-handing-off-to-teams`         | "handoff meeting", "writing child epics", "go/no-go"                         | Phase 4 (Scoping & Commitment) deep-dive — architecture plan, child epics, per-team handoffs, leadership commitment. |
| `coordinating-implementation-across-teams` | "support period", "monthly stakeholder update", "closing out the initiative" | Phase 5 (Implementation) deep-dive — shepherd coordinates teams executing the initiative.                            |
| `contributing-to-technical-strategy`       | "cross-team pattern of pain", "surfacing ideas to architecture"              | How team-level patterns flow up into the TSI backlog and back down through initiatives into team epics/stories.      |

## Installation

```bash
/plugin install bitwarden-initiative-tools@bitwarden-marketplace
```

```
What's my role at the scoping & commitment phase of the funnel?
```
